## 一、研发背景

企业开始将 AI Agent 接入 SQL 查询工具、CI/CD 发布工具、配置中心、运维工具和业务 API。此类 Agent 不再只是生成文本，而是能够触发真实工具执行。若缺乏执行前风险控制，Agent 可能造成生产数据删除、错误发布、关键配置误改或下游系统异常。

本项目围绕“Agent 动手前，先判断会不会出事”的目标开展研发，形成 `agent-safety-gateway` 智能体执行安全网关 MVP。

本项目的研发重点不是将 Agent、资源目录、风险规则、审计页面简单组合成业务管理系统，而是在目标 executor 被调用前形成“请求拦截、动作解析、影响范围识别、风险分级、执行守卫门控、审计记录”的技术控制闭环。

## 二、研发目标

研发目标包括：

1. 在智能体工具调用执行前拦截请求。
2. 将请求解析为动作元组。
3. 识别直接和间接受影响资源。
4. 根据操作、环境、资源、依赖、测试状态和可回滚性生成风险等级。
5. 输出允许、阻断、沙箱、审批或参数改写决策。
6. 通过执行守卫控制 executor 是否被调用。
7. 记录审计证据，并通过前端页面回放。

## 七、真实性边界说明

当前研发证明材料基于本地 MVP 和确定性验证：

- Agent 使用 deterministic Agent Adapter。
- SQL、CI/CD、配置中心 executor 使用 mock executor。
- 数据源和流水线为本地 fixture。
- 审计存储为 JSON/JSONL 本地存储。

因此，本材料可证明技术方案已完成可运行的本地实现和执行控制闭环，但不能宣称已经完成真实生产系统接入。正式提交前建议补充真实 Agent、SQL 沙箱、CI/CD dry-run、配置中心沙箱的复验材料。
