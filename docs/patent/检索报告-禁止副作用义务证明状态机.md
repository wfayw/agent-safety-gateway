## 1. 检索目标

检索是否已有公开方案披露以下完整组合：

```text
AI agent 可调用工具执行器
+ 根据 executor 声称能力推导危险能力
+ 生成 NegativeProbePlan
+ 对危险能力执行主动拒绝探测
+ 生成 DeniedCapabilityEvidence
+ 对 dry-run / sandbox 执行器采集执行前后快照
+ 计算 SideEffectDeltaEvidence
+ 生成 ExecutorSafetyEvidenceVersion
+ 凭据、网络、endpoint、runner 或 namespace 漂移触发重探测
+ RequiredExecutionMode 与安全证据版本匹配
+ permit 绑定 safetyEvidenceVersion / evidenceHash
+ 证据缺失时 permitIssued=false 且 executorInvoked=false
```

```text

```

## 3. 检索结论

### 3.1 不能确认“没有近似公开方案”

不能确认不存在近似公开方案。本轮检索发现以下近似方向：

1. OPA Gatekeeper / Kubernetes policy 中已有 container capabilities、disallowed capabilities、required drop capabilities 等准入控制公开。
2. dry-run、sandbox、副作用隔离、admission control、broker、attestation、secret release 等基础构件已有大量公开。
3. AI agent 工具访问、MCP server attestation、agent runtime identity、capability declaration / denied capabilities 等方向已有近似公开。
4. 一些公开资料使用“negative capability signals”或“denied capabilities”术语，但语境与本案不同。
5. 软件自动测试领域已有观察 side-effects、记录相关对象变化、重复执行并比较结果的专利公开。
6. 智能助手系统中已有使用 dry runs 进行候选 agent / policy 选择的公开。

因此，不能写成“已确认没有近似公开方案”。

### 3.2 未发现完整同构组合

在本轮公开资料检索中，未发现明确同时公开以下完整组合的资料：

```text
AI agent 工具执行器
+ 根据 executor claimedCapabilities 推导危险能力
+ 生成 NegativeProbePlan
+ SQL readonly 写入/删除/DDL 拒绝探测
+ dry-run / sandbox 执行前后快照采集
+ SideEffectDeltaEvidence 证明 forbidden effects 未发生
+ ExecutorSafetyEvidenceVersion 汇总负能力和副作用差异
+ 漂移触发旧证据失效和重探测
+ RequiredExecutionMode 与 safetyEvidenceVersion 匹配
+ permit 绑定 evidenceHash
+ 证据缺失时生成 PermitDeniedEvidence 且 executorInvoked=false
```

严谨结论是：

> 本轮公开资料检索未发现完整同构公开“agent 工具执行器负能力探测 -> DeniedCapabilityEvidence -> SideEffectDeltaEvidence -> ExecutorSafetyEvidenceVersion -> DriftTriggeredReprobe -> RequiredExecutionModeMatch -> permit 绑定 / 拒绝证据”的方案；但已发现 OPA Gatekeeper denied/disallowed capabilities、dry-run/sandbox、attestation/admission/gatekeeper、agent tool attestation、软件测试 side-effect observation 等近似公开，因此本案必须将创造性集中在智能体工具执行器场景下的负能力探测、副作用差异校验、漂移触发重探测和许可绑定的连续组合。

## 6. 对交底书的修改建议

1. 不要写“确认没有近似公开方案”。
2. 主权利要求不要单独写 attestation、signed evidence、broker、dry-run、sandbox 或 denied capabilities。
3. 主权利要求应保留以下连续链路：

```text
claimedCapabilities
-> dangerousCapabilitiesToDeny
-> NegativeProbePlan
-> NegativeProbeResult
-> DeniedCapabilityEvidence
-> SideEffectProbePlan
-> SideEffectDeltaEvidence
-> ExecutorSafetyEvidenceVersion
-> DriftTriggeredReprobe
-> RequiredExecutionModeMatch
-> PermitBinding / PermitDeniedEvidence
```

4. `DeniedCapabilityEvidence` 必须写成主动探测结果，而不是配置声明。
5. `SideEffectDeltaEvidence` 必须包含执行前后快照、forbiddenEffectsObserved、effectDelta。
6. 漂移触发因素必须具体化：credentialFingerprint、networkPolicyFingerprint、endpoint、runner image、namespace。
7. permit 绑定必须绑定 `safetyEvidenceVersion` 和 evidence hashes。

## 7. 授权可能性更新

由于本轮检索发现 denied capabilities、dry-run、sandbox、attestation、admission、agent tool attestation、软件测试 side-effect observation 等近似公开，应继续保持保守。

| 申请版本 | 授权可能性判断 |
| --- | --- |
| 宽泛 Agent Safety Gateway / guardrail | 低，约 15%-25% |
| 宽泛 executor attestation / signed profile | 中低，约 25%-40% |
| 宽泛 deniedCapabilities / dry-run / sandbox | 中低，约 25%-40% |
| 当前负能力探测 + 副作用差异校验组合但无工程 MVP | 中等偏低到中等，约 40%-50% |
| 补齐 SQL/CI/CD/config 真实 probe、effect delta、drift reprobe、permit binding MVP 后 | 中等，约 50%-65%，但仍不建议宣称超过 80% |

## 8. 最终结论

不能确认没有近似公开方案。

本轮公开资料检索可支持的结论是：

> 未发现完整同构公开“AI agent 工具执行器负能力探测 -> DeniedCapabilityEvidence -> SideEffectDeltaEvidence -> ExecutorSafetyEvidenceVersion -> DriftTriggeredReprobe -> RequiredExecutionModeMatch -> PermitBinding / PermitDeniedEvidence”的方案；但已经发现 denied capabilities、dry-run/sandbox、attestation/admission/gatekeeper、agent tool access attestation、软件测试 side-effect observation 等近似公开。申请必须收窄到上述连续组合，并用 SQL、CI/CD、配置中心三类真实探测证据支撑。
